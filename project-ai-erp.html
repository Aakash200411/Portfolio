RAG-based ERP assistant

A retrieval-augmented FAQ assistant for an ERP system: it finds the most relevant FAQ record by meaning, then has an LLM answer using only that context.

Repository

Overview

Users of an ERP system usually have to dig through menus to find institutional information. This assistant lets them ask in natural language. A question is embedded, matched against stored FAQ records, and the best match is passed to Gemini as context so the answer stays grounded in the ERP’s own data instead of the model’s guess.

How retrieval works

  • Embeddings: FAQ questions are encoded with Sentence Transformers (all-MiniLM-L6-v2) and stored in a FAISS index.
  • Search: the user query is embedded and searched against the index; the closest FAQ (question, answer, category) becomes the context.
  • Generation: Gemini is prompted to answer only from that context, and to say it could not find the answer when the context is irrelevant.
  • Live updates: adding an FAQ in the UI writes to MongoDB and triggers an index rebuild (guarded by a thread lock), so new records are searchable without a restart.
  • Usage tracking: each matched FAQ has its hit count incremented in MongoDB.

Architecture

  • AI service: Python and Flask (/query, /update_index, /health).
  • Backend: Node.js and Express routes for ERP records and FAQ management, with MongoDB models.
  • Frontend: React (Vite, Tailwind) with a dashboard, FAQ form and chat interface.

Limits and next steps

Retrieval currently passes only the single best match to the model, and there is no similarity cutoff beyond the model’s own refusal. Next steps would be passing the top-k matches with a relevance threshold, and a small evaluation set to measure retrieval accuracy.
