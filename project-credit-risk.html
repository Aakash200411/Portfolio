Credit card default prediction

Predicting next-month payment default for 30,000 credit card customers, with model comparison, threshold selection and explainability.

Repository UCI dataset

Overview

Using the UCI "Default of Credit Card Clients" dataset (30,000 customers, 22.12% default rate), I built a binary classifier for next-month payment default. The work covers EDA, repayment-behaviour feature engineering (credit utilization, payment-to-bill ratio, delay counts), pipeline-based preprocessing, eight-model comparison with stratified cross-validation, tuning, threshold optimisation and explainability.

Key results

0.5650cross-validated PR-AUC for XGBoost, the best of eight candidate models (LightGBM 0.5599, Random Forest 0.5543, Logistic Regression 0.5052)
0.79ROC-AUC on the untouched test set
92.77%recall at a 0.10 threshold (precision 28.82%), against 35.72% recall and 67.71% precision at the default 0.50

The model is only useful once the threshold matches the business question. At 0.10 it catches nearly every defaulter but flags many safe customers for review; at 0.50 it is precise but misses most defaults. I chose 0.10 on the validation split by maximising F2 and report both so the trade-off is explicit.

PR-AUC was the primary metric because the classes are imbalanced. Sigmoid calibration did not help (Brier 0.1339 vs 0.1332 raw), so I kept the raw probabilities.

What drives default

  • Most recent repayment status (PAY_0) was the strongest signal under permutation importance.
  • Engineered features ranked next: maximum delay status, delayed-month count and credit utilization.
  • SHAP was used for global and single-customer explanations. These are predictive associations, not causes.

Method

  • 80:20 stratified split with a separate validation partition; preprocessing kept inside pipelines so cross-validation stays leakage-free.
  • Class weighting and SMOTE tested, with resampling applied only inside training folds.
  • RandomizedSearchCV for tuning; the test set was used once, at the end.
  • Interactive prediction demo inside the notebook (probability, class, risk label).

Limits

This predicts credit card payment default for one historical population, not general loan default, and the project is for analysis and prioritising accounts for human review rather than approving or pricing credit. Demographic variables such as age and sex raise fairness questions I have not yet evaluated across groups.
